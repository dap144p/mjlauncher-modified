# MJLauncher Modified v1.11.1 — AFK hotfix preview

This is a **test build** from MJLauncher Modified v1.11 preview (not official MJ).

- Android ID: `git.artdeell.mjlaunch.modified`
- Android manifest versionName: `justicia-h1-v1.11.1-hotfix`
- Android manifest versionCode: `554`
- Signed with the same private signing identity as v10/v1.11 (key **not included** in source).
- The original 97 native libraries, 20-session DEX and renderer catalog remain unchanged.

## Implemented

1. The game's `GameActivity.onPause` calls the existing native AFK hidden flag; `onResume` restores the shown flag. `onStart`/`onStop` remain as existing fallbacks. Background is determined per Android game process.
2. The Java engine intercepts OpenAL `alSourcef(AL_GAIN)`, `alSourcePlay`, listener-gain and listener-position call sites. When the game sound thread next processes an intercepted call, tracked source volume is set to zero and restored after foreground. It does **not** globally mute Android audio.
3. The existing render gate and swap suppression remain. Zero presented frames do not mean zero client-side tick work. The render loop keeps its previous ~20 Hz pacing safety ceiling; slowing the main game thread to 1 Hz risks disconnects.
4. Read-only GLFW startup probes log the `glfwInit`, `glfwGetPrimaryMonitor`, `glfwGetVideoMode`, and `glfwCreateWindow` results without changing them.

## Not fixed / not guaranteed

- **Minecraft 1.13.x–1.14.x startup NPE is NOT FIXED**: the same crash occurs in the official MJ launcher. Logs from the updated build can help isolate the GLFW failure.
- OpenAL mute transitions depend on game sound-thread calls; a continuously playing sound with no subsequent intercepted OpenAL call may still be audible until the next callback.
- No ability to guarantee Android won't kill a background process or that Minecraft servers won't disconnect for AFK.
- No device test completed. The local Java-agent integration test checks source mute/restore and pass-through GLFW probes; Android lifecycle hooks are statically verified in smali.

## Build, locally (no keystore in Git)

Prerequisites: Java/JDK 17, Apktool 2.11.1, ASM jars and Disassemble.java from user's private v10 build backup. This ZIP contains the changed Java source and scripts but no APK, signing key, passwords or cached accounts.

```bash
bash patches/build-engine-v111.sh /path/to/afk-deps build/afk-engine-v1111.jar
python3 patches/apply-v1111-to-v111.py --base-apk /path/to/v1.11-preview.apk --apktool /path/to/apktool.jar --agent-jar build/afk-engine-v1111.jar --output build/unsigned-v1111.apk
python3 patches/sign-v1111.py --base-apk /path/to/v1.11-preview.apk --unsigned build/unsigned-v1111.apk --keystore /private/v10-signing.p12 --password-file /private/store-password.txt --agent-jar build/afk-engine-v1111.jar --output build/v1.11.1.apk
```

## Useful game logs

Look for `[MJ AFK] presentation=suppressed` and `[MJ AFK] OpenAL tracked sources=... muted=true` when app goes to background. On Minecraft 1.13–1.14 startup, look for `[MJ GLFW] primaryMonitor=` and `[MJ GLFW] videoMode=` to determine whether a null video mode appears before `cub.<init>` / `cfs.<init>` fails.

**Warning**: backup session/account data before replacing any experimental launcher. Testing one session first is safer than immediately running all twenty.
