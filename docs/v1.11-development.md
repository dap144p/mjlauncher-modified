# v1.11 source development

Base: v10, SHA-256 `52d7dcfb6090f2fe3cf079cbda93ba558f13c8fc78bbe21d491939a314fcd828`.

Work implemented on this branch:

- `SessionAfkConfigV111`: write/read atomic per-slot settings and write process-to-slot identity; belongs in the Android launcher, not the game JAR.
- Host-JVM tests checking independent sessions and toggling while running.

Integration needed before releasing an APK:
1. Include `AfkPolicyV111.class` in the v10 relocated Java-agent JAR and have `Bridge.initialize` use it instead of the global-only flag.
2. After `SessionRuntime.attach` and before the game JVM starts, call `SessionAfkConfigV111.recordCurrentProcessSlot(context, SessionRuntime.index())`.
3. Expose `isSessionEnabled/setSessionEnabled` from each slot's settings, without changing global preferences or renderer choice.
4. Implement session manager status, quick controls, crash share and low-RAM warning; test restart/stop in a single session before multi-session stress testing.

**No Android APK is built by this CI workflow.** It validates only the policy's JVM behavior. Do not report successful background-network uptime or 1 FPS fallback until tested on a device.
