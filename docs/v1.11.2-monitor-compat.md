# MJLauncher Modified v1.11.2 — experimental Minecraft 1.13–1.14 monitor compatibility

This patch is **experimental** and not proven to fix on-device Minecraft 1.13.x or 1.14.x. It uses v1.11.1 as the direct base and retains Android package `git.artdeell.mjlaunch.modified`.

## Evidence

The game debug logs for both 1.13 and 1.14 show successful `glfwInit`, available video mode, non-zero primary monitor handle, then NPE at `cfs.<init>(SourceFile:90)` or `cub.<init>(SourceFile:78)`.

An offline check against Mojang's original 1.13 and 1.14 client JARs found that the NPE is caused by the `cfr` / `cty` monitor manager returning a null monitor object from a `Map.get` lookup. The native GLFW root cause remains unknown.

## Patch

`src/afk/.../EngineTransformer.java` looks for the *exact* 1.13/1.14 monitor manager class shape, including both GLFW monitor API references and getter `(J)Lcfj;` / `(J)Lctu;` calling `java.util.Map.get`. It injects a pass-through call before return.

`Bridge.recoverMonitor(...)` only acts if the cached monitor object is `null` **and** the handle is non-zero. It calls the game's existing `a(long,int)` monitor-connected callback (`GLFW_CONNECTED = 0x40001`) and reads the manager's map again. It logs `[MJ GLFW] cfr monitor recovery: ...` or `cty`.

No native monitor pointers are fabricated. An error continues to the original path and gets logged; it may still crash.

## Build locally

Java 8 source target / JDK 17+ tooling. Bring your own valid v1.11.1 signed APK and private signing key. Never add the signing key or password to GitHub.

1. `bash patches/build-engine-v111.sh /path/to/asm-deps build/afk-monitor-fix-v1112.jar`
2. `python3 patches/apply-compat-v1112.py --base ORIGINAL-v1.11.1.apk --agent-jar build/afk-monitor-fix-v1112.jar --out build/unsigned-v1112.apk`
3. Sign using `patches/sign-v1112-local.py` with your existing private v10 certificate. See `--help`.
4. Validate SHA-256 signing fingerprint matches v1.11.1; verify package `.modified`, versionCode 555, original classes DEX + native binaries unchanged.

**Release test APK:** `MJLauncher-Justicia-H1-v1.11.2-113-114-compat-PREVIEW.apk`.

Expected SHA-256: `e162e838e294e917d9ae29e45ad323f7ce2c5a18db7813f4d85059d324c33fb4`.

## Validation

A simulation test with dummy Minecraft 1.13 and 1.14 monitor managers passes; an invalid native monitor handle 0 remains unmodified. A real Android Minecraft startup has **not** been verified.

## What remains unchanged

20-session support, per-session AFK, background audio/render policy, renderer lock and 11 renderer entries, main classes DEX and all original native renderer libraries.
